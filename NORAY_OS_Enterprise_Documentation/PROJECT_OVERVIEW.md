## Mission

NORAY aims to transform how users interact with artificial intelligence by moving beyond traditional chatbots into a fully integrated AI Operating System. The mission is to provide a unified platform capable of understanding user knowledge, retrieving trusted information, coordinating multiple intelligent agents, and assisting users throughout complex workflows such as career development, scholarship discovery, document generation, research, and knowledge management.

## Vision

Within the next 1–3 years, NORAY is envisioned as a capable AI Operating System serving individuals, research groups, and educational institutions. The long-term architectural vision includes:

- Distributed multi-agent intelligence
- Enterprise knowledge management
- Hybrid local + cloud AI
- Autonomous AI workflows
- MCP tool ecosystem
- Multi-tenant organizations
- Enterprise security & governance
- Kubernetes-ready deployment
- AI Notebook & research copilot capabilities

These are architectural aspirations for future phases, not current capabilities — see [`DEVELOPMENT_ROADMAP.md`](./DEVELOPMENT_ROADMAP.md).

## Goals for v1.0

1. Build a production-grade Hybrid RAG pipeline combining dense vectors, sparse retrieval, and intelligent fusion.
2. Develop an AI Operating System rather than a conventional chatbot.
3. Integrate multiple AI providers through a unified LLM Gateway with intelligent routing and failover.
4. Enable document understanding through semantic search, embeddings, and knowledge indexing.
5. Provide an explainable, observable, and extensible architecture suitable for future enterprise deployment.
6. Deliver an intuitive enterprise-grade user interface inspired by modern AI products.
7. Demonstrate a scalable software architecture that extends the RAG concepts required by Digilians Lab 2 and Lab 6 into a real-world AI platform.

## How to Read This Documentation

This project intentionally documents both what has been built and what is still in progress. Every capability is labeled using a three-tier maturity model:

- ✅ **Implemented** — production-ready and working end-to-end.
- 🟡 **Partial** — core architecture and functionality exist; additional providers, UI polish, or production hardening are still in progress.
- ⚪ **Planned** — designed and documented, intentionally not yet implemented.

This is a deliberate choice: the goal of this documentation is technical credibility, not the appearance of completeness.
